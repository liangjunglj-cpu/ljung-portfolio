T.01

WASP-MCP

OPEN SOURCE · V0 SHIPPEDGRASSHOPPER × CLAUDEFOOD4RHINO
// SIMULATION · TEXT PROMPT → LIVE CANVAS
01 · SPEAK

You describe the definition in plain language. Claude resolves it against evidence-backed component knowledge — every node it knows, it knows from documentation, not guesswork.

02 · PLACE

Components land on the live Grasshopper canvas, wired and auto-organised into legible clusters — with explained notes beside each group, so the definition teaches you as it builds itself.

03 · RUN

Wasp discrete aggregation executes on the canvas — parts, rules, stochastic growth — geometry the model composed but Grasshopper computes. Nothing is faked in a chat window.

04 · SEE

Viewport capture feeds back to the model — it looks at what it made, critiques it, and iterates. The loop that makes it a collaborator, not a code generator.

Why it's different: MCPs for CAD usually generate scripts blind. wasp-mcp works on the canvas itself — the model places real components, runs real solvers, and sees real output. Published on Food4Rhino and the Rhino Package Manager; installable with one PowerShell command.

T.02

ALMOND

V1.1CLAUDE → RHINO MCPPHYSICS LOOP
// SIMULATION · GENERATE → SIMULATE → CRITIQUE → REGENERATE
01 · GENERATE

Claude proposes structure in Rhino — not from primitives, but from a repository of real structural elements and, since v1.1, IKEA's actual furniture catalogue, pulled by what you specify.

02 · SIMULATE

The proposal is submitted to Kangaroo form-finding and Karamba structural checks. Gravity is not optional. Members that overstress are named, not hidden.

03 · CRITIQUE

The model reads the physics results and argues with them — a reasoning pass over deflections and utilisation before it touches the geometry again.

04 · REGENERATE

A corrected proposal replaces the first. The loop repeats until the structure is something that is actually possible — AI that can defend what it draws.

Why it's different: generative AI is happy to draw the impossible. Almond closes the loop with physics — every form it proposes has survived simulation and its own critique. Case study: the ARCC Tower, a cable-stayed office mast with spiral stair, guy cables and IKEA-furnished floors — validated end-to-end by the bridge itself: KARAMBA 3.1, HIGH CONFIDENCE, all structural checks OK, deflection 0.0 mm within a 48 mm limit.

RHINO / GH ⇄ KANGAROO · KARAMBA ⇄ REASONING PASS · REPEAT · TCP 5000

T.03

CHESTNUT

SHARP-UROPAI → VRGAUSSIAN SPLATS
LOADING SPLAT · world_basalt.spz · 5.6 MB θ 000°
// THIS IS NOT A SIMULATION — A REAL GENERATED WORLD · SCROLL TO ORBIT iceland basalt formation with ice
01 · PROMPT → WORLD

A sentence goes to World Labs Marble; an explorable Gaussian-splat world comes back — half a million gaussians per world, cached locally as SPZ.

02 · COLLIDE

Each world gets a collider mesh, GLB props and physics, so the space isn't a picture — it has floors you stand on and walls that stop you.

03 · INHABIT

Walk it on desktop or in WebXR on Quest 3, alone or in shared Socket.IO sessions. Paired with Almond, the workflow closes: reason the geometry, then walk inside it.

04 · EVALUATE

A built-in rubric captures spatial coherence, legibility, atmosphere and tectonic failure per world — the platform is both the instrument and the output of the UROP.

Why it's different: AI-to-VR demos show you a scene; Chestnut is a research instrument that logs how AI worlds fail — hallucinated geometry, scale inconsistency, tectonic nonsense — building the failure taxonomy for AI as an architectural medium.

MARBLE API → SPZ → COLLIDER → WEBXR · rubric per world · UROP w/ PROF POON KING WANG

T.05

BETELNUT

MAP-FIRSTGEOSPATIALLIVE MVP
// SIMULATION · GEOJSON → SEMANTIC SYNTHESIS
01 · LOAD

Drop in GeoJSON — parcels, roads, coastlines. The map is the interface; there is no ribbon of five hundred GIS buttons.

02 · ASK

A semantic layer reads the data's meaning, so you ask in design terms — "what falls within 200 m of the shoreline?" — not in SQL.

03 · SYNTHESIZE

QGIS-like operations in the browser — buffers, overlays, spatial joins — plus traffic analysis on custom input models, currently in development.

04 · DECIDE

Results render as planning evidence — built for architects and planners, not GIS specialists, with environmental simulation on the roadmap.

Why it's different: geospatial analysis normally lives in expert desktop software. Betelnut moves the essential synthesis into a map-first browser app where the semantic layer does the GIS translation for you.

GEOJSON → SEMANTIC LAYER → BUFFER / OVERLAY / JOIN → EVIDENCE
